# Проверка двух телефонов и раздельной маршрутизации — 21 октября 2026

## Результат

Настоящий Android VPN/TUN на Wi-Fi-телефоне подключён к выходу на мобильном
телефоне. Соединение между телефонами для этого испытания проходило через
явный временный USB/ADB-мост. **Самостоятельное соединение через интернет
между этими сетями не установлено. USB-мост не является обходом CGNAT.**

Запуск VPN подтверждён пользователем в системном диалоге Android. Существующий
другой VPN на мобильном телефоне не отключался. Исходящие сокеты выхода
PeerNetVPN привязаны к физической мобильной сети штатным PhysicalNetwork.
Скорость перед испытанием измерена реальными HTTPS-пробами, без подстановки.

## Доказательство маршрутов

Два небольших тестовых APK имеют разные пакеты и UID. VPN разрешён только
`org.uzel.probe.vpn`; `org.uzel.probe.direct` исключён. Оба используют обычный
URL.openConnection без привязки к сети, обхода VPN и собственной socket factory.
Проверен HTTPS `api.country.is`, статус 200. Полные IP и локальные журналы
остаются в игнорируемой `.tools`, в публичную документацию не включены.

| Состояние | Приложение | Android VPN transport | Внешний IP |
|---|---|---|---|
| До подключения | выбранное | false | Wi-Fi A |
| VPN работает | выбранное | true | другой адрес B |
| VPN работает | исключённое | false | прежний Wi-Fi A |
| После отключения | ранее выбранное | false | прежний Wi-Fi A |

Во время испытания выходной телефон сообщил одного клиента и 18391 переданный
байт; клиент зарегистрировал 16189 полученных байт. Это разные счётчики
направлений, их равенство не требуется. Ответ выбранного приложения получен
через узел выхода, исключённого — через обычную Wi-Fi-сеть.

Оба LiveDeviceTest завершились `OK (1 test)`. После проверки остановлены
тестовые сессии, восстановлены настройки публичной сети, контакты и выбор
приложений. Все четыре созданные ADB-переадресации удалены. Оба тестовых APK
удалены; основной PeerNetVPN оставлен. Проверено отсутствие TUN PeerNetVPN
на клиенте и сохранение существовавшего другого VPN на мобильном телефоне.

## Почему автономное соединение осталось недоступным

Wi-Fi-роутер ответил на NAT-PMP external-address query частным WAN-адресом
из диапазона 192.168.10.0/24. Внешний адрес Wi-Fi отличается: присутствует
ещё один уровень NAT. Вышестоящий шлюз не ответил на ограниченные запросы
NAT-PMP и HTTP. Пользователь сообщил, что доступа к настройкам роутеров нет
или он неизвестен. У мобильного устройства CGNAT IPv4; у Wi-Fi-телефона
нет маршрута публичного IPv6. Достижимый участник-посредник не предоставлен.

Для работающего соединения без USB нужен хотя бы один достижимый участник:
публичный IPv4 с открытым TCP 39281, доступный обеим сторонам IPv6 либо
проброс порта через оба уровня NAT. В выделенном сервере проекта необходимости
нет, но существующие сетевые ограничения нельзя устранить одной настройкой
выбора приложений. UDP hole punching эта версия не реализует.

## Повторение диагностики

Собрать `:app:assembleDebugAndroidTest`, `:routing-probe-vpn:assembleDebug`,
`:routing-probe-direct:assembleDebug`. APK-зонды используются только для тестов,
не входят в основной APK. LiveDeviceTest по умолчанию лишь читает snapshot.
Активный режим вызывается явно: `action=usbServe` на выходе, затем
`action=usbConnect`, `apps=org.uzel.probe.vpn`, `contact=<public test contact>`
на клиенте. Оба режима ограничены 600 секундами; ранняя остановка — создание
`files/live-device-stop` через run-as. В finally восстанавливаются настройки.
Нельзя выдавать такой тест за доказательство доступности через интернет.

Задача 3: диагностика и аппаратная приёмка. Токены всех агентов, стоимость,
время до принятия пользователем — нет данных. Основная цель автономного
соединения остаётся невыполненной из-за отсутствия достижимого маршрута.
