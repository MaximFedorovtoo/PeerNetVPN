# PeerNetVPN 0.2.0 — 21 октября 2026

Последующая проверка настоящего Android VPN на двух телефонах через временный
USB-мост описана в `device-routing-verification.md`: выбранное приложение
использовало VPN, исключённое — обычную сеть, после отключения маршрут
восстановился. Ограничения ниже отражают первоначальную приёмку сборки.

## Проверено локально

`tools/build.ps1 :core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`
завершился BUILD SUCCESSFUL. JVM: 43 выполненных теста, 0 failures/errors;
семь сценариев NetworkTest повторно выполняются наследующим RelayTest.
Всего 36 различных сценариев. Lint: 0 ошибок, прежнее предупреждение
WakelockTimeout для блокировки CPU на время foreground-службы.

На двух подключённых телефонах (25098PN5AC и OnePlus LE2100) установлена новая
сборка без удаления данных. По пять AppSelection-тестов и UI smoke прошли.
Физический замер загрузки прошёл на cellular и Wi-Fi. После исправлений
отдельно повторён AndroidTransportTest: успешен на обоих устройствах.
Таким образом, все восемь Android-сценариев прошли на каждом телефоне;
последняя повторная проверка выполнялась адресно для изменённого транспорта.

AndroidTransportTest использует три временные AndroidKeyStore-идентичности,
прямое соединение и два подключения к relay. Передаёт и сверяет реальные
echo-байты через сквозной TLS. В тесте используется loopback и синтетический
лимит скорости; он не доказывает прохождение CGNAT между операторами.
Временные ключи теста удаляются, пользовательский ключ не затрагивается.

## Найдено и исправлено проверками

- Повторяющиеся Cache-Control у обоих провайдеров: объединяются все значения,
  сохраняется проверка HTTP 200, no-store/no-cache и пустого тела.
- Conscrypt требует разрешения NONE для подписи уже вычисленного TLS-хеша;
  исходный SHA256-only ключ вызывал INCOMPATIBLE_DIGEST. Ключ v2 исправляет
  совместимость, старый v1 сохранён. Приглашения требуется передать заново.
- Владение relay-сокетом: конец потока больше не закрывает сокет TLS-клиента
  до чтения уже поступившего ответа. Регрессионный тест сначала воспроизвёл
  ошибку, затем прошёл; Android подтвердил исправление.
- Независимый review выявил гонку отзыва public mode и устаревшие результаты
  refresh. Добавлены проверки поколений, закрытие ожидающих публичных сокетов,
  запрет private JOIN при публичной авторизации и проверка TTL перед connect.
  Проверяющий подтвердил устранение замечаний чтением исправленного кода.

## Существенные ограничения

Реальный межсетевой VPN между двумя пользовательскими телефонами не подтверждён.
Мобильное устройство имеет CGNAT IPv4 и глобальный IPv6; Wi-Fi-устройство имеет
частный IPv4, ULA IPv6 и не смогло выполнить внешний IPv6-запрос. Нет подтверждённого
достижимого bootstrap/relay-участника. Подключение требует такого участника либо
доступного адреса/проброса порта; приложение не обещает универсальный обход NAT.

Android allowlist проверен на сохранение, валидацию и пустой список. Системный
VPN/TUN с выбранным сторонним приложением не испытывался: существующий другой
VPN не отключался, системное разрешение пользователя не обходилось.

Замеры провайдеров: `docs/speed-providers.md`. Ограниченный сравнительный
замер прямого пути: `docs/performance-0.2.md`. Доступность провайдеров во всей
России, автономная работа при любом NAT, энергоэффективность и аудит независимой
сторонней организацией не подтверждены.
