# Проверка прямого пути 0.1 → 0.2

Локальный Windows/JDK 17, одинаковый процесс JVM для каждого варианта,
сохранённые с предыдущей проверки классы `.tools/core-test` против текущих
`core/build/classes/java/main`. Скрипт `tools/TransportBenchmark.java` использует
одинаковые API, два узла с измеренной скоростью 3 000 000 байт/с и один
ограничитель 1 000 000 байт/с. Выход разрешён на loopback только в тесте.

Перед замером генерируются ключи и устанавливается сессия. Первый обмен —
прогрев; затем пять обменов по 128 КиБ в каждую сторону с проверкой всех байтов.
Время включает открытие потоков и TLS, но не генерацию ключей и начальный JOIN.

| Вариант | Пять обменов | Суммарный полезный поток | Активные Java-потоки |
|---|---:|---:|---:|
| Сохранённый 0.1 | 2745,2 мс | 477454 байт/с | 7 |
| 0.2 | 2666,1 мс | 491627 байт/с | 7 |

Один короткий прогон не доказывает ускорения или отсутствия регрессий во всех
условиях. В этом сценарии заметного ухудшения не выявлено. CPU, пиковая память,
энергопотребление телефона и производительность через реальные операторские
сети не измерены. Для relay старой реализации для сравнения нет; отдельный
тест проверяет общий ограничитель relay и выхода, а не рекорд пропускной способности.
