# УЗЕЛ Android Implementation Plan

> **For agentic workers:** use superpowers:executing-plans; independent UI and toolchain tasks are delegated under AGENTS.md.

**Goal:** Build an installable Android DPN app implementing the approved sharing rules.

**Architecture:** Android VPN + native tun2socks + local SOCKS5 bridge to TLS peer exit.
Pure Java network core tested on loopback. Android service owns lifecycle and physical-network binding.

**Tech Stack:** Java 17, Android SDK 35, AGP 8.9.2, Gradle 8.13, hev 2.18.0.

**Spec:** docs/design.md

## Global Constraints

- No traffic credits; receiving requires available sharing.
- At most three authenticated devices; one aggregate upload limiter at measured speed / 3.
- Eight locales; no fake connection states.
- No project-operated servers; direct connectivity limitations disclosed.

## Review Focus

- Multiple streams from one device must not exhaust device slots or evade aggregate pacing.
- Peer/network loss must invalidate leases and close existing forwarding sockets.
- Failed authentication and private-network destinations must fail closed.
- Speed measurements must not recursively require an existing client lease.
- Android service/UI lifecycle must not report connected before the TUN and control session work.
