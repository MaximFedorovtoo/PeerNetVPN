# Каталог PeerNet на Synology

Служба хранит в памяти подписанные объявления и зашифрованные сообщения
сопряжения. Она не является выходным VPN-узлом и не пересылает пользовательский
интернет-трафик. Перезапуск очищает каталог; активные участники публикуются вновь.

## Сборка и размещение

Локально: `powershell -ExecutionPolicy Bypass -File tools/build-bootstrap.ps1`.
Два файла из `dist/synology` поместить в отдельную папку проекта Container Manager.
Создать проект из подготовленного `docker-compose.yml`.
Используется официальный ARM64-совместимый Eclipse Temurin JRE 17.
Контейнер запускается непривилегированным пользователем, без capabilities,
с read-only файловой системой и read-only доступом только к JAR программы.
Память ограничена 192 MiB, Java heap — 96 MiB. JVM использует один активный CPU.
На этом NAS ядро не поддерживает CFS-квоту CPU и лимит PID: параметр CPU удалён,
лимит PID игнорируется Docker. Это не жёсткие ограничения ресурсов.

Порт 39282 опубликован только на loopback NAS. Для телефонов нужен отдельный
HTTPS reverse proxy к `http://127.0.0.1:39282`, с действительным сертификатом.
Не направлять к приложению административный адрес DSM, не отключать проверку
сертификатов и не заменять существующие службы. Адрес HTTPS задаётся в приложении.

Проверки: `GET /health` отвечает `ok`, `POST /v1/exchange` принимает бинарный
кадр до 128 KiB. Остальные маршруты отсутствуют. Каталог содержит максимум
256 объявлений и 128 сообщений, до 8 сообщений от одной личности. Это не
защита от создания множества новых личностей: публичный сервер имеет ограниченную
ёмкость и может потребовать дополнительной защиты от злоупотреблений.
Четыре обработчика, очередь 16, общий срок соединения 10 секунд и ограничения
частоты ограничивают ресурсы. За reverse proxy лимит применяется к адресу
прокси: входящие X-Forwarded-For не считаются доверенными.

## Приёмка

До реального развёртывания успешная локальная сборка не означает, что служба
доступна из интернета. Требуется проверка HTTPS на обоих телефонах, затем
AutoDiscoveryDeviceTest и проверки маршрутизации выбранного/исключённого приложения.
Существующий прямой канал должен продолжить работу после выключения bootstrap.
После потери всех достижимых участников стартовая точка снова нужна.
